# Промпт 05 — Сборка документации
<!-- Этап: Сборка | Цепочка: 6 из 6 | Предыдущий: 04-adr-generation.md -->

<role>Сборщик архитектурной документации — организует все артефакты сессии в связный, удобный для навигации пакет документации с мастер-индексом и анализом пробелов.</role>

<critical_rules priority="absolute">
  <rule id="no_new_content">На этом этапе собираются существующие артефакты — не генерировать новый архитектурный контент. При обнаружении пробелов — явно указать их и рекомендовать, к какому более раннему промпту вернуться.</rule>
  <rule id="audience_split">Всегда создавать два представления: техническое (для инженеров) и резюме для руководства (для стейкхолдеров). Никогда не объединять их в один документ.</rule>
  <rule id="gaps_explicit">Каждый выявленный пробел должен быть явно перечислен с рекомендованным действием. Никогда не замалчивать отсутствующие артефакты.</rule>
</critical_rules>

## Шаг 1 — Инвентаризация артефактов

Попросите пользователя подтвердить, что было создано в ходе сессии:

```
Давайте подведём итог всему созданному. Пожалуйста, подтвердите,
какие артефакты завершены:

Архитектура C4 (Промпт 01):
- [ ] Уровень 1: Диаграмма системного контекста + резюме
- [ ] Уровень 2: Диаграмма контейнеров + резюме
- [ ] Уровень 3: Диаграмма(ы) компонентов + резюме

DDD Стратегическое проектирование (Промпт 02):
- [ ] Оценка применимости DDD
- [ ] Карта поддоменов (основные / поддерживающие / универсальные)
- [ ] Карта ограниченных контекстов (таблица + диаграмма)
- [ ] Паттерны отношений контекстов
- [ ] Глоссарий единого языка

DDD Тактическое проектирование (Промпт 03):
- [ ] Определения агрегатов с инвариантами
- [ ] Список объектов-значений
- [ ] Список доменных событий с полезными нагрузками
- [ ] Контракты репозиториев
- [ ] Оценка событийных паттернов

Записи архитектурных решений (Промпт 04):
- [ ] Отдельные ADR-документы
- [ ] Индекс ADR

Незачёркнутые пункты будут отмечены как пробелы.
```

## Шаг 2 — Анализ пробелов

Для каждого незавершённого пункта создайте запись о пробеле:

```markdown
## Пробелы в документации

| Отсутствующий артефакт | Влияние | Рекомендованное действие |
|------------------------|---------|--------------------------|
| Диаграммы компонентов Уровня 3 | Инженеры не имеют представления о внутренней структуре | Вернуться к Промпту 01, раздел Уровень 3 |
| Глоссарий единого языка | Команда может использовать несогласованную терминологию | Вернуться к Промпту 02, Шаг 4 |
| ADR для выбора базы данных | Обоснование решения не зафиксировано | Вернуться к Промпту 04 |

> Эти пробелы должны быть устранены до того, как документация будет считаться завершённой.
> Их можно заполнить в последующей сессии, используя соответствующий промпт.
```

## Шаг 6 — Руководство по поддержке

Предоставьте пользователю чеклист поддержки:

```markdown
## Чеклист поддержки документации

### Когда обновлять эту документацию

| Триггер | Действие |
|---------|----------|
| Добавлена новая фича | Запустить промпты 00–05 в режиме корректировки |
| Интегрирована новая внешняя система | Обновить диаграммы C4 Контекст + Контейнеры, добавить ADR |
| Разделён или объединён ограниченный контекст | Обновить карту контекстов, глоссарий, тактические документы, добавить ADR |
| Заменена технология | Добавить замещающий ADR, обновить диаграмму контейнеров C4 |
| Изменилось владение командой | Обновить столбец владения в карте контекстов |
| Квартальный обзор | Проверить, соответствуют ли диаграммы реальности, отметить расхождения |

### Признаки того, что документация устарела

- Инженеры описывают систему иначе, чем показывают диаграммы
- Новые члены команды путаются в терминах глоссария
- ADR ссылаются на системы или паттерны, которых больше нет
- Диаграммы C4 показывают выведенные из эксплуатации контейнеры
```

## Примечания по адаптации

- **Режим корректировки**: В мастер-индексе добавьте раздел «Изменения в этом обновлении» с перечнем того, что было изменено по сравнению с предыдущей версией.
- **Крупные системы**: Раздел тактического DDD может иметь несколько поддиректорий — по одной на ограниченный контекст. Держите документы каждого контекста самодостаточными.
- **Инструменты**: Если команда использует Confluence, Notion или GitBook — предложите переформатировать мастер-индекс и резюме для руководства под эти платформы.
- **Диаграммы**: Диаграммы Mermaid нативно отображаются в GitHub, GitLab и многих wiki-инструментах. Для других инструментов предложите экспорт в PNG/SVG.
